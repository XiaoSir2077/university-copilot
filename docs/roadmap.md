# University Copilot · 产品与技术路线图

> 最高约束：**这个项目是软考高项的「母项目」，为考试服务，不为项目牺牲备考。**
> 备考主线：2026.09 打基础 → 2026.12 强化 → 2027.03 真题+论文冲刺 → 2027.05 考试。
> 项目投入上限：备考期每周 ≤ 3 小时（只在周六整块时间做），冲刺期（2027.03 起）冻结新功能。

---

## 一、让弟弟妹妹真正用起来（产品层，按「打开理由」排序）

孩子们会不会用，取决于**有没有每天打开的理由**。按粘性强弱排序：

### Wave 1 · 打开的理由（2026.09–10，软著前完成）

| # | 功能 | 解决的问题 | 工作量 |
|---|------|-----------|--------|
| 1 | **资讯自动采集流水线**（P2b） | 时间线是死的，看两次就没劲了。定时抓东师/中南邓迪官网 → AI 摘要 → 按月份进各自时间线 | 中 |
| 2 | **每日推荐卡** | 首页顶部每天推一条「和你有关」的资讯/任务，给打开一个具体理由 | 小 |
| 3 | **私信闭环** | 现在孩子发私信只有模拟回执；你回复后孩子端看不到。打通：你面板回复 → 孩子私信频道可见 | 小 |
| 4 | **打卡正反馈** | 连续打卡 streak 🔥、每周自动生成一张「本周学习小总结」卡 | 小 |

### Wave 2 · 真的有用（2026.10–11，软著提交后）

| # | 功能 | 解决的问题 | 工作量 |
|---|------|-----------|--------|
| 5 | **AI 助手接真实 LLM** | 现在规则引擎只能识别「我想…」；接真实模型后可以问学习问题、聊学校事务 | 中 |
| 6 | **动物学教材拆解页** | 妹妹给的书 → 拆原文章节 + 你的笔记 → 互动学习页（学习板块的旗舰内容） | 大 |
| 7 | **真实后端 + 多设备同步** | 现在数据锁在单浏览器；换手机/平板就清零。这是「真的用上」的硬前提 | 大 |
| 8 | **改密码 / 找回机制** | 现在改密要改代码重新部署 | 小 |

### Wave 3 · 考试后（2027.06 起）

- 管理面板升级「家庭 OKR」：弟弟妹妹的学期目标、月度回顾
- 弟弟的共学项目跟踪（C/Python 路线）
- 托福备考资料库（TPO 挂到学习板块）

## 二、你的管理面板：架构学习页 + 母项目管理（核心诉求）

### 2.1 「架构学习页」（满足"学技术原理"）

在管理面板加一页 `/architecture`，用**这个项目自己**讲清每个技术决策，每节标注对应的软考考点：

| 主题 | 用项目里的什么讲 | 对应软考考点 |
|------|----------------|-------------|
| 前端工程化 | Vite + React + TS + Tailwind 为什么这样搭 | 信息化/软件开发技术 |
| 组件与状态管理 | zustand store、组件拆分、props 单向数据流 | 软件架构风格、MVC |
| 路由与权限 | HashRouter 为什么适配静态托管、角色守卫怎么实现 | 信息安全（访问控制）、部署 |
| 认证原理 | 密码哈希（SHA-256+盐）、前端守卫 vs 服务端守卫的局限 | 密码学、安全架构 ⭐ |
| 数据层 | localStorage 架构 → 为什么要上后端（索引、事务、并发） | 数据库、缓存 |
| 构建与 CI/CD | npm build → dist → plumbing 推送 → Pages 发布 | 持续集成 ⭐ 案例题素材 |
| 需求管理 | 弟弟妹妹的诉求 = 需求池，状态机（pending→in_progress→done） | 范围管理、变更控制 ⭐ |
| 干系人管理 | 四种角色（管理员/孩子/只读）权限矩阵 | 干系人管理 ⭐ |
| 成本与风险 | 免费层部署的取舍、GitHub Pages 国内访问慢的风险登记 | 成本/风险管理 ⭐ |

⭐ = 论文十大知识领域直接素材。这个页面同时是**论文素材发生器**：你每学一节，沉淀一段"我在 University Copilot 项目中具体做了什么"。

### 2.2 「母项目管理」面板（把项目当软考案例管）

管理面板加一个项目维度，直接产出论文素材：

- **需求池**：孩子诉求 = 干系人需求（已有，补「需求变更记录」）
- **里程碑**：软著提交（2026.10）、后端上线（2026.11）、LLM 接入…
- **风险登记册**：考期冲突、Pages 国内访问、免费后端额度
- **项目日志**：你每周写 3-5 句"本周做了什么决策"，年底导出 = 论文背景素材库

## 三、与备考时间表的协同（关键）

| 时间 | 备考主线 | 项目动作 | 为什么 |
|------|---------|---------|--------|
| 2026.09 剩余 | 第一章打基础 | ① 架构学习页 v1 ② 资讯采集 MVP ③ **软著材料整理** | 论文素材要趁早期写 |
| 2026.10 | 继续基础期 | **软著提交**（用本项目代码+文档，你是前3完成人）→ 之后只做私信闭环/打卡反馈 | 软著是 E 类认定硬条件，越早越好 |
| 2026.11–2027.02 | 系统强化（12周） | **功能冻结**，只维护；采集流水线自动跑 | 案例分析专项启动，项目不许抢时间 |
| 2027.03–04 | 真题+论文冲刺 | 完全冻结；项目日志照写（这是论文期，项目日志=素材） | 每两周写 1 篇完整论文 |
| 2027.05 | 考试 | 只修严重 bug | |
| 2027.06– | 领证、E 类认定 | Wave 3：后端迁移、LLM、教材拆解页 | |

**架构学习页是唯一的"备考+项目"交集**：它既是产品功能，又是你的学习材料——做它不算挤占备考时间，算案例学习。

## 四、技术选型备忘（到时候再定，先记结论）

- **后端**：优先 Cloudflare（Pages 国内访问优于 GitHub Pages；D1/KV 免费层够用）；备选 Supabase。迁移时数据模型照搬现有 `FamilyDB`。
- **LLM**：接你已有的方舟 arkcli 通道（evaluateSisterInput 接口不变，内部换实现——这就是「接口隔离」的现成案例）。
- **采集**：定时任务（Kimi Work Automation 或 GitHub Actions cron）→ 抓取 → LLM 摘要 → 写入后端。

## 五、风险登记册（项目自身的）

| 风险 | 概率 | 对策 |
|------|------|------|
| 项目抢备考时间 | 高 | 每周 ≤3h 硬上限；冲刺期冻结 |
| 功能做完孩子不用 | 中 | 先上 Wave 1 四个"打开理由"，观察一周打开率再决定 Wave 2 |
| GitHub Pages 国内访问不稳 | 中 | 影响使用就迁 Cloudflare（已在选型内） |
| 软著材料拖延 | 中 | 架构学习页写完即作为软著文档初稿 |

## 六、待思考的设计问题（用户设计角度，持续补充）

### 关于真实使用场景
1. 弟弟妹妹**什么时候会打开**这个应用？睡前、课间、周末？它要替换掉他们现有的什么行为（而不是在已经爆满的信息流里再加一个）？
2. 弟弟在全英文授课环境里，界面要不要做中英切换？妹妹是生物师范，两个孩子的内容形态差异应该有多大——同一个产品框架，到什么程度就该"分叉"？

### 关于诉求闭环（核心体验）
3. 孩子提了需求之后，**多久没有反馈会失去信心**？"进度随时同步"具体是什么形态——打开时看到？还是主动推送（微信/邮件）？推送的边界在哪，什么算打扰？
4. 当您的评估结果是"不可行/暂缓"，孩子看到什么？**拒绝也是产品体验**——"需要再评估"和"不行"在界面上应该有区别吗？
5. 什么该进待办清单、什么只是聊天？规则引擎的判断边界孩子能理解吗——误判一次，孩子还会再信这个入口吗？

### 关于家庭关系与隐私
6. 措辞客观化之后，「私信」频道出现了一个真实张力：**孩子需要知道自己在对谁说话**。"客观"和"明确对话对象"怎么平衡？完全匿名的对面会让孩子不安还是更敢说真话？
7. 舅舅舅妈真的会打开网页看吗？只读用户的真实场景可能是"微信里直接收到一张本周摘要卡"——只读角色是否值得单独设计一种交付形态（大字版/截图卡/微信推送）？
8. 聊天记录、诉求记录对孩子来说是"被看见感"还是"被监控感"？孩子长大了（比如妹妹大二、大三）还需要这个功能吗，**退出机制**怎么设计？

### 关于长期演化
9. 打卡断签那天，设计是惩罚（streak 清零）还是鼓励（"断一天没关系，明天继续"）？哪种更符合您想传递的家庭价值观？
10. 一年后妹妹毕业/弟弟换校区，账号和内容怎么归档？这个产品的"生命周期"您设想过吗——工具会过时，关系不会。
11. 当"论文/简历叙事"（AI 产品、多角色权限系统）和"孩子真正需要的功能"冲突时，**听谁的**？这个问题的答案决定了这个项目是产品还是作业。
